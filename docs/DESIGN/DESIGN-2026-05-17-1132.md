# システム設計書 - StreaMu AAC PoC Seek Support
**RDD:** `RDD-2026-05-17-1131.md`
**作成日:** 2026-05-17

## 1. 全体方針
- AAC PoC の seek は `/stream_aac_adts?i=<video_id>&t=<seconds>` で扱う。3DS 側は MP4/fMP4 を解析せず、従来通り ADTS だけを受信する。
- サーバー側は fMP4 の `moov/mdhd` から timescale、`moof/traf/tfdt` から fragment の絶対開始時刻、`tfhd/trun` から sample duration/size を読み、目標秒以前の AAC sample を ADTS 出力から除外する。
- `yt-dlp` が fragments を返す場合は、fragment duration の累積から目標秒を含む fragment に近い位置から取得を始める。初期化 fragment は必ず先に送る。
- fragments がない direct URL では、先頭の `sidx` から segment の byte range を解決し、HTTP Range で目標秒付近の `moof/mdat` から取得する。`sidx` がない場合のみ解析失敗として扱う。
- 3DS 側の seek 失敗は「曲終端」ではなく再生失敗として扱い、自動次曲を誘発しない。

    if info.fragments:

- fragments 主経路:
  - `info.fragments[0]["url"]` から `&sq=0` に置換した init URL を作る。
  - `_fragment_start_index()` で開始 fragment を選ぶ。
  - init URL を feed して `moov` を解析させる。
  - `fragments[start_idx:]` を順番に fetch し、各 chunk を `transmuxer.feed()` に渡す。
  - `tfdt` の絶対時刻により、開始 fragment 内でも目標秒以前の sample は捨てる。
- direct URL fallback:
  - `Range: bytes=0-1048575` で先頭を取得し、`ftyp/moov/sidx` を初期化データとして `transmuxer.feed()` へ渡す。
  - `sidx` の reference duration/timescale から開始 segment を選び、各 segment を `Range` で取得する。
  - `tfdt` の絶対時刻により、開始 segment 内でも目標秒以前の sample は捨てる。
- ログ:
  - 開始時に `AAC ADTS stream started: <id> seek=<t>s fragments=<n>` を出す。
  - エラー時は既存の `AAC ADTS stream error` に集約する。

## 4. 各機能の詳細設計

### FR-1: AAC PoC seek 操作
```text
SearchScreen/PlayingScreen/HomeScreen
  -> ctx.seek_target_seconds = target
  -> action "seek"
  -> main.cpp seek branch finds current Track
  -> start_playback(track)
  -> get_audio_stream_url(track.id, target, AacAdtsPoc)
  -> /stream_aac_adts?i=<id>&t=<target>
```

- `ctx.playback_start_time` は既存通り `osGetTime() - target*1000` とし、seek bar は buffering 中に `pause_started_at` で凍結する。
- `seek_target_seconds` は `start_playback` 開始時に必ず `-1` へ戻す。

### FR-2: サーバー側時間指定 ADTS 配信
```text
stream_aac_adts
  -> validate id
  -> clamp t
  -> aac_adts_generator(id, t)
  -> extract/cache AacFormatInfo
  -> fetch init + selected fragments
  -> Mp4AacTransmuxer(start_seconds=t)
  -> feed fMP4 boxes
  -> emit ADTS frames where sample end time > target time
```

- sample 判定は `sample.decode_time + sample.duration <= target_time` を skip とする。
- direct URL で `sidx` がある場合は、`sidx` reference で目標秒を含む byte range から取得を始める。
- `tfdt` がない fragment は `base_decode_time=0` として扱わず、`ValueError` にしてログへ出す。seek 精度が保証できない fragment は出力しない。
- `tfhd`/`trun` で sample duration が得られない場合も `ValueError` とする。

### FR-3: seek 後の継続操作
- `AacPocPlayer::stop()` は seek 前に呼ばれるため、decoder と NDSP buffer は既存通り reset される。
- seek 後の ADTS は stream 先頭として扱えるので、`AacAdtsStreamDecoder` の追加状態は不要。
- 再 seek は同じ `start_playback(track)` 経路を再利用する。

### FR-4: MP3 Proxy 回帰防止
- MP3 Proxy の URL は現状の `/stream?i=<id>&t=<seek>` を維持する。
- `source/network/youtube_api.cpp` の変更は AAC 分岐内に限定する。
- `source/main.cpp` のエラー扱い変更は seek 要求時の自動次曲抑止に限定し、通常の非 seek 再生失敗時の既存動作は維持する。

### FR-5: 不正 seek 位置・失敗時の扱い
- `t` の query parameter は `_clamp_seek_seconds()` で `0..86400` に収める。
- video id 不正は従来通り 400。
- AAC 抽出失敗は 502、direct URL/fragments とも得られない場合は 501。
- streaming 中の解析失敗は generator 内でログに残し、接続を閉じる。3DS 側は `start_streaming()` 失敗として扱う。

## 5. 状態設計（新規フラグ・状態変数がある場合）

新規状態変数は追加しない。既存状態の扱いのみ明確化する。

| 変数 | 型 | 初期値 | セット条件 | クリア条件 | 残留リスク |
|------|----|--------|-----------|-----------|-----------|
| `ctx.seek_target_seconds` | `int` | `-1` | UI の seek 操作で目標秒を設定 | `start_playback` 冒頭、seek 対象 track が見つからない時、stream 失敗時 | 残留すると次回通常再生が seek 再生になる |
| `ctx.is_buffering` | `bool` | `false` | `start_playback` 開始時 | player が実際に wave buffer を queue した時、download thread 完了時 | true 残留で seek bar が凍結し続ける |
| `MP3Player::is_playing` / `AacPocPlayer::is_playing` | `bool` | `false` | `start_playback` で選択中 audio path に応じてセット | stop、stream 失敗、track 終了 | seek 失敗時に true 再セットすると自動次曲になる |

## 6. 実装順序
1. `server/aac_transmux.py` に timescale/tfdt/trun duration 対応と sample skip を追加する。
2. `server/proxy.py` に `t` 受け取り、fragment/sidx 開始位置選択、`aac_adts_generator(v_id, t)` を実装する。
3. PC 上で `/stream_aac_adts?i=dQw4w9WgXcQ&t=30` の先頭 ADTS sync と、`t=0` の回帰を確認する。
4. `source/network/youtube_api.cpp` の AAC URL 生成で `&t=` を許可する。
5. `source/main.cpp` の seek 失敗時自動次曲抑止と `seek_target_seconds` クリアを実装する。
6. `make clean && make` を実行する。ヘッダレイアウト変更は予定しないが、既存 dirty tree に header 変更があるため clean build を行う。
7. 手動実機テストで AAC PoC seek、AAC PoC 通常再生、MP3 Proxy seek 回帰、seek 失敗時の挙動を確認する。
