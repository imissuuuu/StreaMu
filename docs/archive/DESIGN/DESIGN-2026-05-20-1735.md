## 4. 各機能の詳細設計

### FR-1 / FR-4: 通常再生 Opus flow
```text
start_playback(track)
  -> selected_path = ctx.config.audio_path
  -> ctx.active_audio_path = selected_path
  -> Opus: ctx.opus_pending_decode_start = true
  -> YouTubeAPI::get_audio_stream_url(..., OpusDirect)
  -> /stream_opus_ogg bytes are downloaded into g_stream_buffer_ptr
  -> download_thread sets ctx.is_downloading = false
  -> main loop sees opus_pending_decode_start
  -> opus_player.start(buffer.data, buffer.size)
  -> opus_player.update queues NDSP buffers
```

データフローと所有権:
```text
[server/proxy.py]
  YouTube native Opus/WebM bytes
    -> WebM Opus to Ogg Opus remux
    -> HTTP response bytes

[YouTubeAPI::start_streaming]
  response chunks
    -> copy into global g_stream_buffer_ptr under stream_lock

[main loop]
  g_stream_buffer_ptr.data()/size() short-lived pointer
    -> OpusPocPlayer::start()
    -> OpusMemoryDecoder::open()

[OpusMemoryDecoder]
  holds opusfile decoder state that references the memory buffer until reset()
```

所有権ルール:
- `g_stream_buffer_ptr` が Ogg Opus bytes の所有者。
- `OpusMemoryDecoder` は buffer を所有しない。`opus_player.stop()` まで `g_stream_buffer_ptr` を clear / resize しない。
- fallback、stop、search、exit では必ず `opus_player.stop()` を先に呼び、その後に `g_stream_buffer_ptr` を clear する。
- `g_stream_buffer_ptr->data()` の pointer は関数呼び出し中だけ取得し、保持しない。

### FR-2 / FR-3: Settings/config
```text
Settings Audio Path:
  AAC Direct -> Opus Direct -> MP3 Proxy -> AAC Direct

config string:
  "aac_direct" -> AAC_DIRECT
  "opus_direct" -> OPUS_DIRECT
  "mp3" -> MP3_PROXY
  unknown/missing -> AAC_DIRECT
```

### FR-5: fallback
Fallback 発火点:
- `get_audio_stream_url()` callback が empty URL を返した。
- `download_thread` の `api->start_streaming()` が retry 後も失敗した。
- download 完了後の `opus_player.start()` が失敗した。
- `opus_player.has_decode_failed()` が true になった。

Fallback flow:
```text
Opus failure
  -> if !ctx.opus_fallback_attempted
       active path = MP3_PROXY
       current_stream_url = /stream?i=<playing_id>
       MP3Player::is_playing = true
       OpusPocPlayer::is_playing = false
       status = "Opus fallback"
     else
       stop playback and clear playing_id
```

`ctx.config.audio_path` は保存設定なので fallback では変更しない。

リトライ方針:
- 既存 `download_thread` の stream retry は維持し、Opus でも同じ1回 retry を通す。
- retry 後も失敗した場合だけ MP3 fallback を1回試す。
- fallback 先 MP3 の失敗時は再 fallback せず停止する。

一時メッセージ:
- `Opus seek unsupported` は同じ start playback 内で `Buffering...` に上書きしない。Opus URL request を出した後も表示される。
- download 開始後、再生開始時の既存処理で `Playing` に上書きされる。
- `Opus fallback` は fallback download 中から playback 開始まで表示し、再生開始後に `Playing` へ上書きする。

### FR-6: 既存経路保持
- `MP3_PROXY` は `/stream?i=...&t=...` と `MP3Player` のまま。
- `AAC_DIRECT` は `/stream_aac_adts?i=...&t=...` と `AacPocPlayer` のまま。
- `L + R + Y` Vorbis PoC は変更しない。
- `L + R + X` Opus PoC は local file 再生として残す。

## 5. 状態設計

| 変数 | 型 | 初期値 | セット条件 | クリア条件 | 残留リスク |
|------|----|--------|-----------|-----------|-----------|
| `ctx.active_audio_path` | `AudioPathConfig` | `AAC_DIRECT` | 通常再生開始、fallback、hidden PoC start | stop/search/exit で config 値に戻す | config 参照と混ざると別 player update の原因 |
| `ctx.opus_pending_decode_start` | `bool` | `false` | Opus 通常再生開始 | `opus_player.start()` 成否確定、stop/search/exit | true 残留で古い buffer を decode する |
| `ctx.opus_fallback_attempted` | `bool` | `false` | MP3 fallback 発火時 | 新規再生、stop/search/exit | false 残留で fallback loop、true 残留で次曲 fallback 不能 |
| `OpusPocPlayer::decode_failed_` | `bool` | `false` | `op_read()` error、`start()` failure | `stop()` | true 残留で次回 Opus が即失敗扱い |

エラーパス:

| エラー | 処理 | 表示 |
|--------|------|------|
| Opus URL 生成失敗 | MP3 fallback | `Opus fallback` |
| `/stream_opus_ogg` download 失敗 | MP3 fallback | `Opus fallback` |
| Ogg Opus decoder open 失敗 | MP3 fallback | `Opus fallback` |
| Opus decode 中失敗 | MP3 fallback または停止 | `Opus fallback` / `Opus failed` |
| fallback も失敗 | 全 player stop、`playing_id` clear | `Stream Error` |

状態変数の最終値:

| パス | `active_audio_path` | `opus_pending_decode_start` | `opus_fallback_attempted` | active player |
|------|----------------------|-----------------------------|---------------------------|---------------|
| Opus download 成功、decoder open 成功 | `OPUS_DIRECT` | `false` | `false` | `OpusPocPlayer` |
| Opus URL 生成失敗 | `MP3_PROXY` | `false` | `true` | `MP3Player` |
| Opus download 失敗 | `MP3_PROXY` | `false` | `true` | `MP3Player` |
| Opus decoder open 失敗 | `MP3_PROXY` | `false` | `true` | `MP3Player` |
| MP3 fallback 失敗 | `MP3_PROXY` | `false` | `true` | none |
| stop/search/exit | `ctx.config.audio_path` | `false` | `false` | none |

責務の所在:
- URL 生成失敗: `start_playback` の callback。
- download 失敗: `download_thread`。
- decoder open / decode 失敗: main loop。
- stop/search/exit cleanup: input handling 側の既存停止処理。

    - `parse_audio_path("opus_direct") == OPUS_DIRECT`
    - `parse_audio_path("unknown") == AAC_DIRECT`
    - `audio_path_to_string(OPUS_DIRECT) == "opus_direct"`
13. 手動/実機確認:
    - Settings で `AAC Direct -> Opus Direct -> MP3 Proxy` と切り替わり、保存復元できる。
    - Opus Direct で代表曲が通常再生 flow から鳴る。
    - Opus Direct 失敗時に MP3 Proxy fallback する。
    - MP3 Proxy と AAC Direct の通常再生が回帰しない。
    - Hidden `L + R + X` Opus PoC が残る。
