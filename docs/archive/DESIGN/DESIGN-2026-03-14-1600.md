## 1. 全体方針

タッチ状態管理を共通構造体 `TouchState` に集約し、各画面で再利用する。
タッチ処理は `update()` 内で `hidTouchRead` + `hidKeysDown(KEY_TOUCH)` + `hidKeysHeld(KEY_TOUCH)` で行う。

`main.cpp` に `u32 kHeld = hidKeysHeld();` を追加し、Screen の `update()` シグネチャに `kHeld` を追加する。

## 2. 新規ファイル

### 2.1 `source/ui/touch_state.h`

```cpp
#pragma once
#include <3ds.h>

struct TouchState {
    bool is_touching  = false;  // 現在タッチ中か
    bool is_dragging  = false;  // ドラッグモード中か
    int  start_x      = 0;     // タッチ開始X
    int  start_y      = 0;     // タッチ開始Y
    int  prev_y       = 0;     // 前フレームY
    int  current_x    = 0;     // 現フレームX
    int  current_y    = 0;     // 現フレームY

    static constexpr int DRAG_THRESHOLD = 4; // px

    // タッチ開始時に呼ぶ
    void begin(int x, int y) {
        is_touching = true;
        is_dragging = false;
        start_x = x;
        start_y = y;
        prev_y  = y;
        current_x = x;
        current_y = y;
    }

    // タッチ継続中に毎フレーム呼ぶ。ドラッグ時のY差分を返す
    int update(int x, int y) {
        current_x = x;
        current_y = y;
        int delta_y = 0;

        if (!is_dragging) {
            int dy = current_y - start_y;
            if (dy > DRAG_THRESHOLD || dy < -DRAG_THRESHOLD) {
                is_dragging = true;
            }
        }

        if (is_dragging) {
            delta_y = prev_y - current_y; // 上方向スワイプ = 正 = リスト下にスクロール
        }

        prev_y = current_y;
        return delta_y;
    }

    // タッチ終了時に呼ぶ。タップだったかを返す
    bool end() {
        bool was_tap = is_touching && !is_dragging;
        is_touching = false;
        is_dragging = false;
        return was_tap;
    }

    void reset() {
        is_touching = false;
        is_dragging = false;
    }
};
```

### 3.4 `source/main.cpp`

**kHeld の取得:**
```cpp
u32 kDown   = hidKeysDown();
u32 kHeld   = hidKeysHeld();   // ← 追加
u32 kRepeat = hidKeysDownRepeat();
```

**screen_mgr.update() 呼び出し:**
```cpp
std::string action = screen_mgr.update(ctx, kDown, kHeld, kRepeat);
```

**ポップアップタッチ処理（各 STATE_POPUP_* ブロックに追加）:**
```
1. hidTouchRead(&touch)
2. kDown & KEY_TOUCH → touch_state.begin()
3. kHeld & KEY_TOUCH → touch_state.update() でドラッグ差分取得
4. タッチ離れ（前フレーム touch 中、今フレーム非タッチ）
   → touch_state.end() で was_tap 判定
   → タップ先の座標からポップアップ項目のインデックスを計算
   → ポップアップ外タップなら previous_state に戻す
```

ポップアップのタッチ項目判定:
```
item_index = (tap_y - (box_y + POPUP_HEADER_H + 4)) / POPUP_ITEM_H + start_idx
```
ポップアップ外判定:
```
tap_x < POPUP_MARGIN_X || tap_x > POPUP_MARGIN_X + POPUP_WIDTH ||
tap_y < box_y || tap_y > box_y + box_h
```

```
1. 既存の SEARCH_BTN 挿入処理（変更なし）

2. タッチ処理（新規）:
   touchPosition touch;
   hidTouchRead(&touch);

   if (kDown & KEY_TOUCH)
       ctx.touch_state.begin(touch.px, touch.py);

   if (kHeld & KEY_TOUCH && ctx.touch_state.is_touching)
       delta_y = ctx.touch_state.update(touch.px, touch.py);
       ctx.scroll_offset_y += delta_y;  // ドラッグスクロール
       clamp scroll_offset_y

   if (!(kHeld & KEY_TOUCH) && ctx.touch_state.is_touching) {
       was_tap = ctx.touch_state.end();
       if (was_tap) {
           // タップ位置から項目インデックスを計算
           tapped_index = (touch.py + scroll_offset_y - BTM_LIST_START_Y) / BTM_ITEM_HEIGHT_2ROW + btm_start;

           // 戻るボタン判定 (x:4-44, y:206-236)
           if (tap in back_button_area) → return back action

           if (tapped_index == ctx.selected_index)
               → 実行（SEARCH_BTN / toggle_pause / start_playback）
           else
               ctx.selected_index = tapped_index;
       }
   }

3. 既存の KEY_A 処理（変更なし）
4. navigate_track_list()（変更なし）
```

## 5. 戻るボタンの共通描画

各画面の `draw_bottom()` で個別に描画する（共通関数化は不要、描画コード3行程度）。

```cpp
// 戻るボタン描画（ポップアップ中は非表示）
if (ctx.current_state != STATE_POPUP_*) {
    C2D_DrawRectSolid(4, 206, 0, 40, 30, ctx.theme->text_dim & 0x40FFFFFF); // 半透明背景
    C2D_TextParse(&text, buf, "B");
    // テキスト中央揃え
    C2D_DrawText(&text, ..., 16, 212, ...);
}
```

ただし、ポップアップ判定は `draw_bottom` の `RenderContext` では `current_state` で判別可能。
実際にはポップアップ中は `draw_popup_overlay()` が上から描画されるので、
戻るボタンは常に描画しても問題ない（ポップアップに隠れるため）。

→ **結論: 常に描画する。ポップアップ中のタッチ判定のほうで戻るボタンのタップを無視する。**

## 6. ドラッグスクロールの scroll_offset_y 管理

### リスト画面（Search / Playlists / PlaylistDetail）

- `scroll_offset_y` は `RenderContext` に追加
- ドラッグで `scroll_offset_y` を増減
- 描画時: 各項目のY座標を `y_pos - scroll_offset_y_clamped` で計算する代わりに、
  **scroll_offset_y をインデックスに変換**して `start_idx` を決定する方式を採用

理由: 現在の描画ロジックが `start_idx` ベース（`btm_scroll`）で動いているため、
ピクセル単位のスクロールより整合性が取りやすい。

```
計算式:
  scroll_index_offset = (int)(scroll_offset_y / BTM_ITEM_HEIGHT_2ROW)
  → btm_scroll に加算
```

- DPad操作時は `scroll_offset_y = 0` にリセット（DPadは自動追従なので）
- 画面遷移時（on_enter）で `scroll_offset_y = 0` にリセット

### クランプ:
```
max_scroll = max(0, (total_items - max_visible) * BTM_ITEM_HEIGHT_2ROW)
scroll_offset_y = clamp(scroll_offset_y, 0, max_scroll)
```

### ポップアップ
- ポップアップは項目数が少ないため、ドラッグスクロールは不要（DPad自動追従で十分）
- 将来的に長いプレイリスト一覧を追加する場合にのみ検討
