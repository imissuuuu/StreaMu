# システム設計書 - StreaMu FFmpegless Audio PoC
**RDD:** `docs/RDD/RDD-2026-05-17-ffmpegless-audio-poc.md`
**作成日:** 2026-05-17

## 1. 全体方針
- 既存 `/stream` MP3 経路は変更せず、AAC PoC は別 endpoint / 別 decoder / 設定切替で横に追加する。
- YouTube の `mp4a` は多くが `audio/mp4` / fragmented MP4 なので、3DS 側へ MP4 demuxer を持ち込まない。サーバー側で FFmpeg を使わずに AAC access unit を ADTS に軽量 transmux し、3DS 側は ADTS AAC decoder だけを扱う。
- 3DS 側 decoder は PoC 専用に `AacPocPlayer` として `MP3Player` から分離する。共通バッファ `g_stream_buffer_ptr` と download thread は流用し、既存 playback / playlist / seek bar の状態遷移を最小変更にする。
- AAC decoder 候補は Helix AAC を第一候補にする。devkitPro portlibs には AAC / libavcodec / FAAD が無いため、PoC では `third_party/helix-aac/` に vendored source を置く前提にする。ライセンスは RPSL 系で、正式リリース同梱前に別途判断する。
- `miniaudio` は stock decoder が AAC を含まないため採用しない。FAAD2 は GPL-2+ 扱いなので MIT 配布に混ぜる前提では採用しない。

## 2. 新規ファイル

### `3ds-music-player/source/audio/aac_poc_player.h`
レイヤー: infrastructure/audio。責務は「ADTS AAC バイト列を PCM16 に decode し ndsp へ投入する」ことだけ。

```cpp
#ifndef AAC_POC_PLAYER_H
#define AAC_POC_PLAYER_H

#include <3ds.h>
#include <stdint.h>
#include <vector>
#include "aac_decoder_helix.h"

class AacPocPlayer {
public:
  AacPocPlayer();
  ~AacPocPlayer();

  bool init();
  void update();
  void stop();
  bool is_track_finished() const;
  bool has_started_playing() const;
  void set_downloading_status(bool downloading);

  static bool is_playing;

private:
  AacDecoderHelix decoder_;
  ndspWaveBuf wave_buf_[8];
  int16_t *audio_buffer_;
  bool is_downloading_ = false;
  size_t read_offset_ = 0;
};

#endif
```

API契約:
- 入力: `g_stream_buffer_ptr` 内の ADTS AAC bytes。所有者は download thread、読み取りは `stream_lock` 下で行う。
- 出力: ndsp channel 0 へ PCM16 interleaved を投入。
- エラー: decode 不能時は `read_offset_` を進めず、その frame で `update()` を終了する。連続失敗の扱いは `main.cpp` の status 更新で行う。
- 副作用: ndsp channel 0、linearAlloc領域、`AacPocPlayer::is_playing`。

### `3ds-music-player/source/audio/aac_decoder_helix.h`
レイヤー: infrastructure/codec adapter。Helix C API を StreaMu 内の narrow API に閉じ込める。

```cpp
#ifndef AAC_DECODER_HELIX_H
#define AAC_DECODER_HELIX_H

#include <stdint.h>
#include <stddef.h>

struct AacDecodeResult {
  bool ok;
  int bytes_consumed;
  int samples_per_channel;
  int sample_rate;
  int channels;
};

class AacDecoderHelix {
public:
  AacDecoderHelix();
  ~AacDecoderHelix();

  bool init();
  void reset();
  AacDecodeResult decode_adts_frame(const uint8_t *data, size_t size,
                                    int16_t *pcm_out, int pcm_capacity_samples);

private:
  void *decoder_;
};

#endif
```

API契約:
- 入力: ADTS sync word から始まる bytes。MP4 container bytes は受け付けない。
- 出力: PCM16 interleaved。`samples_per_channel` は 0 または正数。
- エラー: `{ok:false, bytes_consumed:0}`。呼び出し側は追加入力待ちか stream error 判定を行う。
- 副作用: Helix decoder 内部状態のみ。

### `3ds-music-player/source/audio/aac_decoder_helix.cpp`
Helix API の呼び出しをここに限定する。

想定呼び出し:
```cpp
decoder_ = AACInitDecoder();
int sync = AACFindSyncWord(inbuf, bytes_left);
int rc = AACDecode(decoder_, &inbuf, &bytes_left, pcm_out);
AACFrameInfo info;
AACGetLastFrameInfo(decoder_, &info);
```

`AACDecode()` 後の `bytes_consumed` は `before_bytes_left - after_bytes_left` で計算する。

### `3ds-music-player/server/aac_transmux.py`
レイヤー: infrastructure/server-side pure-ish parser。MP4/fMP4 の AAC samples を ADTS frames に変換する。ネットワークI/Oは持たない。

```python
from dataclasses import dataclass
from typing import Iterable

@dataclass(frozen=True)
class AacCodecConfig:
    profile: int
    sample_rate: int
    sample_rate_index: int
    channels: int

@dataclass(frozen=True)
class Mp4Sample:
    data: bytes
    duration: int

class Mp4AacTransmuxer:
    def feed(self, chunk: bytes) -> list[bytes]:
        """Return zero or more ADTS frames."""

    def flush(self) -> list[bytes]:
        """Return pending ADTS frames or raise ValueError on incomplete state."""
```

不変条件:
- `AacCodecConfig.sample_rate_index` は ADTS の 0..12 のみ。
- `channels` は 1 または 2 のみ許可。3ch以上は PoC では unsupported。
- 出力 frame は必ず ADTS 7-byte header + AAC raw access unit。

初期対応範囲:
- progressive M4A: `ftyp` + `moov` + `mdat`
- fragmented M4A: init segment + `moof`/`mdat` fragments
- unsupported atom / encrypted stream / sample table不足は `ValueError`。

```cpp
void YouTubeAPI::get_audio_stream_url(const std::string &video_id,
                                      int seek_seconds, AudioPath path,
                                      StreamCallback callback) {
  std::string url = get_base_url();
  if (path == AudioPath::AacAdtsPoc) {
    if (seek_seconds > 0) {
      callback("", false);
      return;
    }
    url += "/stream_aac_adts?i=" + video_id;
  } else {
    url += "/stream?i=" + video_id;
    if (seek_seconds > 0) url += "&t=" + std::to_string(seek_seconds);
  }
  callback(url, true);
}
```

## 4. 各機能の詳細設計

### FR-1 / FR-7: FFmpegless 判定材料
`docs/POC/ffmpegless-audio-poc.md` に各段階の結果を追記する。実装中に判断を混ぜず、以下の3段階で判定する。

| 段階 | 成功条件 | 失敗時の判断材料 |
|------|----------|------------------|
| Server extract | `/api/aac-info` が `mp4a` を返す | YouTube側で安定してAACが取れない |
| Server transmux | `/stream_aac_adts` が ADTS を返す | MP4/fMP4 parser の実装負荷が高い |
| 3DS decode | 実機で短い曲が再生される | decoder性能/ライセンス/メモリが不適 |

### FR-2 / FR-3: yt-dlp mp4a抽出
データフロー:
```text
YouTube video id
  -> server/aac_probe.extract_aac_format()
  -> AacFormatInfo
  -> server/proxy.py:/api/aac-info JSON
  -> server/proxy.py:/stream_aac_adts generator
```

`AacFormatInfo` の所有者:
- 生成: `aac_probe.extract_aac_format`
- 消費: `aac_info`, `aac_adts_generator`
- キャッシュ: 既存 `_url_cache` とは分け、`_aac_info_cache: dict[str, tuple[AacFormatInfo, float]]` を `proxy.py` に置く。

### FR-4: 3DS AAC直接decode
データフロー:
```text
/stream_aac_adts HTTP bytes
  -> YouTubeAPI::start_streaming()
  -> g_stream_buffer_ptr
  -> AacPocPlayer::update()
  -> AacDecoderHelix::decode_adts_frame()
  -> ndsp channel 0 PCM16
```

所有権:
- `g_stream_buffer_ptr`: 既存通り global unique_ptr。書込は network callback、読込は player。
- decode中に vector 参照を長く保持しない。`stream_lock` 下で必要範囲を読んで、decode 呼び出し後に即 unlock する。
- `AacDecoderHelix` は `AacPocPlayer` が値として所有する。

### FR-5: 既存MP3 fallback
`AudioPathConfig::MP3_PROXY` を default にする。AAC PoC の失敗時に自動で MP3 へ再試行するかは実装段階で入れない。理由は、失敗分類を曖昧にしないため。ユーザーが Settings で戻せる設計にする。

エラー表示:
- AAC endpoint URL生成失敗: `AAC PoC Unsupported`
- AAC stream HTTP失敗: 既存 download error path で `Extract Error (Check Proxy)` または `Stream Error (Offline?)`
- AAC decode失敗: `AAC Decode Error`

### FR-6: Android APK判断
Android project は今回変更しない。PoC結果だけ `docs/POC/ffmpegless-audio-poc.md` に残し、Android APK 側の FFmpeg 同梱判断は次フェーズへ送る。

| 変数 | 型 | 初期値 | セット条件 | クリア条件 | 残留リスク |
|------|----|--------|-----------|-----------|-----------|
| `AppConfig::audio_path` | `AudioPathConfig` | `MP3_PROXY` | Settings保存、config読込 | 不正値読込時は `MP3_PROXY` | `AAC_ADTS_POC` のまま release すると未検証経路が既定化される。defaultで防ぐ |

|------|----------------------|--------------------|--------------------------|-----------------------------|--------------------|
| AAC URL生成失敗 | false | false | false | false | `AAC PoC Unsupported` |
| HTTP stream失敗 | false | false | false | false | 既存 stream error |

## 6. 実装順序
1. Server: `aac_probe.py` と `/api/aac-info` を追加する。
   - Checkpoint A: PC browser/curl で JSON が返る。
2. Server: `aac_transmux.py` と `/stream_aac_adts` を追加する。
   - Checkpoint B: PC上で先頭 bytes が ADTS sync `0xFFF` になることを確認する。
3. 3DS: `AudioPathConfig` と config/settings 切替を追加する。
   - Checkpoint C: `make clean && make` PASS。MP3既定で既存再生経路がビルド上壊れていない。
4. 3DS: `AacDecoderHelix` / `AacPocPlayer` を追加し、AAC PoC 経路だけで呼ぶ。
   - Checkpoint D: `make clean && make` PASS。
5. 3DS: `main.cpp` の start/update/stop 分岐を接続する。
   - Checkpoint E: MP3 path clean build PASS。
6. PoC記録: `docs/POC/ffmpegless-audio-poc.md` に server-side 結果を記録する。
7. 手動実機テスト項目を出す。
   - Codex は emulator / adb / 実機起動を行わない。

- Server unit-ish:
  - `aac_probe.extract_aac_format(video_id)` が `acodec` `mp4a` の format を返す。
  - `Mp4AacTransmuxer.feed()` がサンプル `mdat` から ADTS header付き frame を返す。
  - unsupported sample では `ValueError` を返し、HTTP 501 に変換される。
- 3DS build:
  - `C:\devkitPro\msys2\usr\bin\bash.exe -lc '/c/dev/3ds-music-player/build.sh clean'`
- Regression:
  - `Audio Path = MP3 Proxy` の default で既存 `/stream` URLが生成される。
  - seek `t > 0` は MP3 path のみ。AAC path では URL生成失敗にする。
- Manual runtime:
  - Settingsで `AAC PoC` に切替。
  - 短い非ライブ動画を再生。
  - 音が出る/出ない、status message、サーバーログを記録。
  - 失敗後に `MP3 Proxy` へ戻して既存再生が可能か確認。

## 9. リスクと判断ゲート
- MP4/fMP4 transmuxer が想定より複雑な場合、AAC直接再生は「サーバー抽出は可能、FFmpegless transmuxが高コスト」と分類する。
- Helix AAC のライセンスは正式配布前の判断ゲートにする。PoC成功だけで release asset に含めない。
- AAC patent/licensing は配布判断の別課題。PoC結果には技術可否と配布可否を分けて書く。
- header layout 変更があるため、実装後は必ず clean build を行う。
