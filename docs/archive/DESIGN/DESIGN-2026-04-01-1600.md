# Web Research Skill

検索・評価フェーズの実行手順。

## Step 1: クエリ生成
- 質問を短いキーワードに変換（1〜3語が理想）
- 同義語・関連語も含めてカバレッジを広げる
- 英語と日本語の両方でクエリを検討する

## Step 2: スニペット取得
- `full-web-search` ツールを使用
- `limit: 10`, `includeContent: false` でまずスニペットのみ取得
- 0件のときは別のクエリで最大2回まで再試行する
- 複雑なトピックは2クエリに分けて検索し結果を統合する

## Step 3: スニペット評価
- 各結果のタイトル・スニペットを読み、有益かどうか判断する
- 関連性が低いものは除外する
- Trusted Sources（優先して参照）:
  - コーディング・技術: 公式ドキュメント > GitHub > Zenn > Qiita
  - 一般: 公式サイト > Wikipedia

## Step 4: 全文取得
- 有益と判断したURLを `browser-use` MCP で全文取得する
- 複数ソースで内容が一致する情報を優先する

## Step 5: 保存
- 以下のフォーマットで `C:/dev/qwen/research-reports/<topic_snake_case>.md` に保存
- 保存後、ファイルパスを出力する

### Output Format

\```
# [調べたトピック]

## 結果
- 内容 [[ソース名](URL)] ※最終更新: YYYY-MM
- 内容 [[ソース名](URL)]

## 参照ソース
- [タイトル](URL) — 最終更新: YYYY-MM（不明な場合は省略）

## アクセス失敗URL（該当がある場合のみ）
- [URL] — 理由（タイムアウト / 403 / etc.）
\```
```

```markdown
---
name: web-research
description: Delegate web research to Qwen (local LLM) which uses web-search + browser-use MCP to save Claude tokens. Use this skill whenever the user wants to look something up, research best practices, compare tools/libraries, or ask "how does X work?" — even if they don't say "research". Trigger on phrases like "調べて", "リサーチして", "ベストプラクティス", "どんな方法がある？", "〜って何？", "〜を比較して", or any question that benefits from up-to-date web knowledge.
---

## Execution Steps

### 1. Build prompt
Construct a structured prompt for Qwen:

\```
## 調査テーマ
<テーマ（具体的に）>

## 調査目的・背景
<なぜこの調査が必要か、何の判断に使うか>

結果を /c/dev/qwen/research-reports/<filename>.md に保存して。
\```

- `<filename>`: descriptive snake_case name for this research topic
- If the question is ambiguous, use **AskUserQuestion** to clarify first.

### 2. VRAM確認
**AskUserQuestion**: "Qwenリサーチを開始します。llama-serverが停止中の場合は自動起動します（VRAM ~5.6GB）。続けますか？"
- Denied → abort

### 3. Execute (background)
Run with `run_in_background: true`（サーバー起動・リサーチ・クリーンアップすべてスクリプトが管理）:
\```bash
bash /c/dev/.claude/skills/web-research/scripts/research.sh "<prompt>" "<filename>.md"
\```

After launching, tell the user:
> 「リサーチをバックグラウンドで開始しました。完了次第お知らせします。」

Then continue with other work or wait for user input.

### 4. On task-notification
When you receive a task-notification for this background task:

- **Success** (exit 0): Read `/c/dev/qwen/research-reports/<filename>.md` and summarize in bullet points.
  - Key findings
  - What's directly applicable
  - If relevant: propose adding to `HANDOFF/phases.md` Planned
- **Error / hung** (`ERROR: qwen hung` in output): Notify user that Qwen failed to start research. Suggest retrying.
- **Timeout** (`TIMEOUT` in output): Answer from Claude's own knowledge instead.

Keep the summary short. The user can ask for detail or read the full file.
```
