# RDD - 2026-03-25-1800
**Project Name:** Buffering Timeout（ストリーミングタイムアウト追加）

## 1. 機能一覧

### 機能要件
- **FR-1**: ストリーミング接続（`start_streaming`）にデータ無受信タイムアウトを追加する

### 非機能要件
- **NFR-1**: タイムアウト値は15秒（検索APIと統一）
- **NFR-2**: 正常なストリーミング中（データが流れ続けている間）は中断しない

## 2. 詳細仕様

### FR-1: ストリーミングタイムアウト
- 入力: ストリーミングURL（proxy.pyの`/stream`エンドポイント）
- 処理: CURLの`CURLOPT_LOW_SPEED_LIMIT` + `CURLOPT_LOW_SPEED_TIME`を使用。15秒間データ受信速度が閾値（1 byte/s）以下の場合、接続を中断する
- 出力: タイムアウト時は`start_streaming()`が`false`を返す → 既存のエラーハンドリング（リトライ → `"Stream Error (Offline?)"` 表示）がそのまま動作

### なぜ `CURLOPT_TIMEOUT` ではなく `LOW_SPEED` か
- `CURLOPT_TIMEOUT`は全体の経過時間で切る → 長い曲の正常ストリーミング中にも発火してしまう
- `LOW_SPEED`はデータが流れなくなった場合のみ発火 → サーバー停止・ネットワーク断のみ検出
