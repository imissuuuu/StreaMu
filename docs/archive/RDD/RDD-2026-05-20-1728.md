# RDD - 2026-05-20-1728
**Project Name:** Opus Audio Path Promotion

## 1. 機能一覧
- FR-1: Hidden PoC の `Opus Direct` を、通常再生で選べる正式な Audio Path 候補へ昇格する。
- FR-2: Settings の `Audio Path` に `Opus Direct` を追加し、`MP3 Proxy` / `AAC Direct` と同じ操作感で選択・保存・復元できる。
- FR-3: config の `audio_path` に `opus_direct` を追加し、既存 config との後方互換を保つ。
- FR-4: 3DS 側の通常再生フローから、サーバーの Opus/Ogg 経路を使って再生を開始できる。
- FR-5: `Opus Direct` 失敗時に、アプリが固まらず既存の fallback 経路へ戻れる。
- FR-6: 既存の `MP3 Proxy` / `AAC Direct` / Hidden Vorbis PoC / Hidden Opus PoC の挙動を壊さない。
- FR-7: `Opus Direct` を正式候補にするが、このタスクでは既定 Audio Path へは変更しない。
- FR-8: Opus 正式候補化後に、AAC Direct からの移行可否を判断できる状態を文書化する。
- NFR-1: `Opus Direct` は FFmpeg runtime dependency を要求しない。
- NFR-2: `Opus Direct` は AAC decoder 同梱を要求しない。
- NFR-3: サーバー側は YouTube native Opus/WebM を再エンコードせず、必要な場合のみ Ogg Opus へ remux する。
- NFR-4: GPL 実装からコードをコピーしない。
- NFR-5: O3DS を含む 3DS のメモリ制約を踏まえ、過大な音声データで安全に失敗できる。
- NFR-6: 正式 release の既定経路変更や AAC decoder の配布方針は、別タスク `AAC Direct Release Gating` で判断する。

## 2. 詳細仕様

### FR-1: 正式 Audio Path 候補化
- 入力: ユーザーが Settings で選択した `Audio Path`。
- 処理: `Opus Direct` が選ばれている場合、通常の曲再生開始時に Opus 用の取得・decode 経路を使う。
- 出力: UI 上は通常の再生と同様に Now Playing / loading / stop / next 操作が動作する。
- 範囲外: このタスクでは `Opus Direct` を既定値にしない。

### FR-2: Settings 選択
- 入力: Settings 画面で `Audio Path` 項目を操作する。
- 処理: `MP3 Proxy`、`AAC Direct`、`Opus Direct` の間で切り替える。
- 出力: 選択値が画面に表示され、Save 後に config に保存される。
- 失敗時: 未知の config 値や古い config は既存の安全な既定値に丸める。

### FR-3: config 後方互換
- 入力: `config.json` の `audio_path`。
- 処理: 既存値 `mp3` / `aac_direct` に加えて `opus_direct` を解釈する。
- 出力: 保存時は選択中の Audio Path を安定した文字列で保存する。
- 互換性: 既存ユーザーの config は変更しない限り従来通り読み込める。

### FR-4: 3DS 通常再生からの Opus 経路
- 入力: YouTube video ID と任意の seek 秒数。
- 処理: サーバーの Opus Ogg endpoint から 3DS が再生可能な byte stream を受け取り、Opus decoder/player へ渡す。
- 出力: 既存プレイヤーと同じライフサイクルで再生、停止、終了検知が行われる。
- 制約: 初期昇格では PoC 実装の安全性を優先し、メモリ上限を超える曲は失敗扱いにできる。

### FR-5: fallback
- 入力: `Opus Direct` の format 抽出失敗、remux 失敗、download 失敗、decode 失敗、サイズ超過。
- 処理: 失敗理由をログまたは status message に残し、既存の fallback Audio Path へ切り替えて再試行できる。
- 出力: ユーザーはアプリ再起動なしで再生継続または別経路への再試行ができる。
- 方針: fallback は `MP3 Proxy` を第一候補とし、AAC Direct への自動 fallback は release gating 方針が決まるまで必須にしない。

### FR-6: 既存経路の保持
- 入力: `MP3 Proxy` / `AAC Direct` を選んだ通常再生、または Hidden PoC 操作。
- 処理: 既存の endpoint、decoder、player、hidden trigger を維持する。
- 出力: 既存テスト項目が従来通り PASS する。

### FR-7: 既定値維持
- 入力: config がない、または `audio_path` が未設定の初回起動。
- 処理: 現在の既定値を維持する。
- 出力: このタスク単体ではユーザーの既定 Audio Path が `Opus Direct` に変わらない。

### FR-8: 移行判断材料の文書化
- 入力: 実装結果、ビルド結果、サーバー確認、実機確認。
- 処理: `Opus Direct` が `AAC Direct` の移行先になれるかを docs に記録する。
- 出力: 次タスクで「Opus を既定化する」「AAC を experimental 化する」「MP3 fallback を残す/削る」を判断できる。

## 3. UI/UX考慮事項
- Settings の `Audio Path` は既存位置を維持し、値だけを3択にする。
- 表示名は `MP3 Proxy`、`AAC Direct`、`Opus Direct` とする。
- `Opus Direct` 選択中でも、検索、再生、停止、次曲、戻る操作は既存の通常操作と同じにする。
- Opus 失敗時は専門的すぎる文言を避け、短い status message で再試行または fallback が分かるようにする。
- Hidden Opus PoC の `L + R + X` は、正式経路が安定するまで開発確認用として残してよい。

## 4. 追加設計情報
- 現在の Opus PoC は `server/opus_probe.py`、`server/webm_opus_remux.py`、`/stream_opus_ogg`、`OpusMemoryDecoder`、`OpusPocPlayer` で成立確認済み。
- PoC の 3DS 側は完全な Ogg Opus buffer を memory decode しているため、正式候補化ではサイズ上限と失敗時挙動を明確にする。
- 既存 config は `source/config_manager.h`、Audio Path enum は `source/ui/theme.h` と `include/network/youtube_api.h` に分かれている。
- Settings の表示・切替は `source/ui/screens/settings_screen.cpp` にある。
- 通常再生の Audio Path 選択は `source/main.cpp` と `source/network/youtube_api.cpp` が中心になる。
- server 側の `/stream_opus_ogg` は現状 full fetch + remux response であり、streaming remux や seek 対応は必要なら DESIGN で段階化する。
- このタスクの完了条件は「Opus が他方式と同様に Settings から選べ、通常再生フローで使える状態」までであり、既定化・AAC 削除・MP3 削除は含めない。
