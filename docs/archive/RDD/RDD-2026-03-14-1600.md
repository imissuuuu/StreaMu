- **FR-1**: リスト画面のタッチ選択（SearchScreen / PlaylistsScreen / PlaylistDetailScreen）

## 2. 詳細仕様

### FR-1: リスト画面のタッチ選択

**対象画面**: SearchScreen、PlaylistsScreen、PlaylistDetailScreen

**動作仕様**:
- タップ（タッチして離す）で項目を選択（`selected_index` 更新）
- 選択済みの項目を再度タップすると実行（DPadのA押下と同じ動作）
  - SearchScreen: SEARCH_BTNならキーボード起動、トラックなら再生開始/一時停止トグル
  - PlaylistsScreen: プレイリスト詳細画面へ遷移
  - PlaylistDetailScreen: 再生開始/一時停止トグル
- タッチ中（ドラッグ判定前）は項目のハイライトを表示

**タップとドラッグの判定基準**:
- タッチ開始位置からY方向に4px以上移動 → ドラッグ（FR-4）
- 4px未満で離す → タップ（選択/実行）

### FR-2: 設定画面のタッチ操作

**通常モード（リスト表示）**:
- 1タップで即座に編集モード開始（項目選択と編集開始を同時に行う）
- Save & Back をタップすると保存して戻る
- セパレータはタッチ対象外

**パレットモード**:
- カラーパレットのセルをタップで直接選択＆確定（色プレビュー即反映）
- パレット外タップは無視

**Hueスライダー**:
- スライダーバー上をタッチすると、そのX位置に応じたHue値（0-360）を設定
- タッチしたままドラッグでリアルタイム値変更

### FR-3: ポップアップのタッチ操作

**対象**: STATE_POPUP_TRACK_OPTIONS、STATE_POPUP_PLAYLIST_ADD、STATE_POPUP_PLAYLIST_OPTIONS、STATE_POPUP_TRACK_DETAILS、STATE_EXIT_CONFIRM

**動作仕様**:
- ポップアップ内の項目をタップで選択＆実行（1タップ即実行）
- ポップアップ項目高さを **20px → 30px** に拡大（タッチしやすさ確保）
- ポップアップ外タップでポップアップを閉じる（B押下と同じ動作）

**レイアウト変更**:
- `POPUP_ITEM_H`: 20 → 30
- `POPUP_HEADER_H`: 20 → 30
- `POPUP_MAX_H`: 190 → 必要に応じて調整（項目数×30 + ヘッダー30）

### FR-5: 戻るボタン（タッチ専用）

**対象画面**: SearchScreen、PlaylistsScreen、PlaylistDetailScreen、SettingsScreen（HomeScreen以外すべて）

**動作仕様**:
- 下画面の左下に「B」と表示された小型ボタンを常時表示
- タップするとDPadのBボタンと同じ動作（前の画面に戻る）
  - SearchScreen → HomeScreen
  - PlaylistsScreen → HomeScreen
  - PlaylistDetailScreen → PlaylistsScreen
  - SettingsScreen → HomeScreen（変更破棄）
- ポップアップ表示中は非表示（ポップアップ外タップで閉じるため不要）

**レイアウト**:
- 位置: 左下（x=4, y=206）
- サイズ: 幅40px × 高さ30px
- テキスト: 「B」（中央揃え）
- 色: テーマの `text_dim` 色、背景は半透明または薄い色

### FR-4: ドラッグスクロール（慣性なし）

**対象画面**: SearchScreen、PlaylistsScreen、PlaylistDetailScreen、ポップアップ

**動作仕様**:
- タッチしたまま指をY方向に動かすとリストがスクロールする
- 指を離すとスクロール停止（慣性なし）
- スクロール量 = 前フレームのタッチY座標 - 現フレームのタッチY座標
- スクロール境界: リストの先頭/末尾を超えないようクランプ

**タップ/ドラッグ判定**:
- タッチ開始時の座標を記録
- Y方向の移動量が閾値（4px）を超えたら「ドラッグモード」に遷移
- ドラッグモード中はタップイベントを発火しない
- タッチを離したときにドラッグモードでなければタップとして処理

### NFR-1: タッチとDPadの共存

- タッチ操作とDPad操作は排他的ではなく、どちらも常に使用可能
- タッチで `selected_index` を更新しても、DPadでそこから継続操作できる
- タッチ操作中はDPadカーソル表示を維持（タッチした項目に移動）

### NFR-2: タッチ判定の最小サイズ

- すべてのタッチ可能な要素は高さ30px以上を確保
- ポップアップ項目: 30px（現在20px→拡大）
- リスト項目（2行表示）: 30px（現在の `BTM_ITEM_HEIGHT_2ROW` = 30px、変更なし）
- 設定項目: 28px（現在の値、許容範囲内）

## 3. UI/UX考慮事項

### タッチ状態管理の共通構造

```
TouchState {
    bool is_touching;        // 現在タッチ中か
    bool is_dragging;        // ドラッグモードか
    int  start_x, start_y;  // タッチ開始座標
    int  prev_y;             // 前フレームのY座標
    int  current_x, current_y; // 現フレームの座標
}
```

各画面の `update()` で以下のフローを実行:
```
1. hidTouchRead(&touch)
2. KEY_TOUCH押下 → タッチ開始（start座標記録、is_touching=true）
3. タッチ中 → Y移動量チェック
   - 閾値超え → is_dragging=true、スクロール処理
   - 閾値以下 → 何もしない
4. タッチ離れ（前フレームtouch中、今フレームtouchなし）
   - is_dragging=false → タップ処理（項目選択/実行）
   - is_dragging=true → ドラッグ終了、何もしない
5. is_touching=false にリセット
```

## 4. 追加設計情報

### 実装上の制約

1. **LightLock**: `g_tracks` / `playlists` アクセス時は必ずロック取得。タッチ判定でインデックスを参照する際も同様
2. **KEY_TOUCH**: `hidKeysDown()` の `KEY_TOUCH` ビットでタッチ開始を検出。`hidKeysHeld()` の `KEY_TOUCH` でタッチ継続を検出。どちらも `kDown` / `kHeld` として `main.cpp` から取得可能
3. **hidTouchRead**: タッチしていない時は `px=0, py=0` を返す。これを「タッチなし」の判定に使用
4. **ドラッグスクロール**: `scroll_offset`（float）を各画面に追加し、描画時のY座標オフセットとして使用。`selected_index` は変更しない
5. **ポップアップの処理箇所**: ポップアップの入力処理は `main.cpp` 内にあるため、タッチ処理もそこに追加する
