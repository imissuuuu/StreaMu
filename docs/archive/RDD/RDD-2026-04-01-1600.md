## 2. 詳細仕様

### FR-1: QWEN.md / SKILL.md 役割分離

**QWEN.md（常時ロード）:**
- 入力: なし（セッション開始時に自動読み込み）
- 処理: 以下を定義
  - 共通ふるまいルール（質問禁止、推測禁止、ローカルファイル閲覧禁止）
  - 調査ワークフロー全体像（クエリ設計→検索→評価→深堀り→レポート）
  - 共通出力ルール（保存先ディレクトリ、ソースURL必須等）
- 出力: Qwenの行動制約・全体方針

**web-research/SKILL.md（検索フェーズ特化）:**
- 入力: スキル呼び出し時にロード
- 処理: 以下を定義
  - 検索フェーズの詳細手順（クエリ生成→検索→スニペット評価→全文取得→保存）
  - 出力フォーマット（Markdownテンプレート）
  - 使用ツール（web-search MCP, browser-use MCP）
- 出力: `C:/dev/qwen/research-reports/<topic>.md`

**将来のスキル拡張（本フェーズではスコープ外）:**
- `query-optimizer/` → クエリ設計フェーズ
- `deep-research/` → 深堀りフェーズ
- `report-writer/` → レポート出力フェーズ

### FR-2: スキル自然発火の最適化

- 入力: 構造化プロンプト（FR-3）
- 処理:
  - QWEN.mdの全体ワークフローで「検索にはweb-researchスキルを使え」と誘導
  - SKILL.mdのdescriptionを具体的なキーワード・トリガー条件で記述（公式推奨）
  - research.shの変更は不要（プロンプトをそのまま渡す）
- 出力: Qwenが自然にweb-research SKILL.mdを発火して従う
- フォールバック: 発火率が低い場合は `/skills web-research` 明示呼び出しに切り替え

### FR-3: プロンプト構造化

- 入力: Claude側SKILL.mdがユーザーの依頼から構築
- 処理: 以下の構造でQwenに渡す
  ```
  ## 調査テーマ
  <テーマ>

  ## 調査目的・背景
  <なぜこの調査が必要か、何の判断に使うか>
  ```
- 出力: research.sh経由でqwenに渡されるプロンプト

### FR-4: 調査失敗検知

- ハング検知: 120秒無出力でkill + エラー通知（実装済み）
- MCP接続失敗: `strictTypes` 警告のみで停止した場合の検知（スキーマ修正で根本解決済み、フォールバックとしてwatchdog維持）
- 検索0件: Qwen側SKILL.mdで「0件のときは別クエリで最大2回再試行」を規定
- 保存失敗: research.sh で `$REPORTS_DIR/$OUTFILE` の存在チェック（実装済み）

### FR-5: Claude側スキル統合

**`.claude/skills/web-research/SKILL.md` 更新:**
- プロンプト構造化（FR-3）の構築ロジック

**`research.sh` 更新:**

- 失敗検知の統合
