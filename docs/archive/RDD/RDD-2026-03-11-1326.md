## 2. 詳細仕様

### 機能A: `rebuild_buttons` キャッシュ化

**現状の問題:**
- `update()` (line 48) と `draw_bottom()` (line 128) の両方で `rebuild_buttons(has_now_playing)` を呼んでいる
- `rebuild_buttons` は `visible_buttons.clear()` → `push_back` × 4~5 で、毎フレーム2回のヒープ操作が発生

**修正方針:**
1. `HomeScreen` クラスに `bool last_has_now_playing_` メンバを追加（初期値 `true` にして初回必ず不一致→リビルド）
2. `rebuild_buttons` を**状態変化時のみ**呼ぶ: `has_now_playing != last_has_now_playing_` の場合のみリビルド
3. `update()` 側で判定＋リビルドし、`draw_bottom()` ではリビルドしない（`update()` → `draw_bottom()` の順で呼ばれることが `main.cpp` のループで保証されているため）

**注意:**
- 初回フレームで `visible_buttons` が空だと `draw_bottom()` でクラッシュするため、コンストラクタまたは `on_enter()` で初回リビルドを行う

### 機能B: レガシー `home_menu` 除去

**除去対象:**
1. `main.cpp:400-405` — `ctx.home_menu = {...}` の構築コード3行 + コメント2行
2. `ui_renderer.h:35` — `RenderContext` 内の `std::vector<std::string> home_menu`
3. `ui_renderer.h:87-88` — `UIRenderer` 内の `t_home_menu`, `last_home_menu`
4. `ui_renderer.cpp:264-273` — `draw_bottom_screen` 内の `STATE_HOME` 描画コード（`ctx.home_menu` を使用）

**安全性確認:**
- `main.cpp:817-818` で `bg_state == STATE_HOME` の場合、`screen_mgr.draw_bottom()` が呼ばれ、`renderer.draw_bottom_screen()` は呼ばれない → `UIRenderer` 側の `STATE_HOME` ブロックは到達不能
