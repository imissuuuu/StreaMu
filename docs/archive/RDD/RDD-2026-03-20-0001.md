# RDD - 2026-03-20-0001
**Project Name:** Startup Loading Improvement

## 1. Requirements List

### Functional Requirements
- **FR-1**: Display a progress bar during startup initialization
- **FR-2**: Progress bar consists of 4 steps (System Init → Config Load → Playlist Load → Server Connection)
- **FR-3**: Redesign the server connection spinner with improved visuals
- **FR-4**: Maintain existing connection timeout handling (Retry / Change IP / Exit menu)
- **FR-5**: Timeout error menu uses D-pad navigation + A button to confirm (no other input methods)
- **FR-6**: Reduce server connection check interval from 1s to 0.5s to improve connection detection speed

### Non-Functional Requirements
- **NFR-1**: Keep current blocking connection approach (no background initialization)
- **NFR-2**: IP input screen (swkbd) remains unchanged. Transition to loading screen should feel natural
- **NFR-3**: Minimize rendering overhead (respect 3DS resource constraints)

## 2. Detailed Specifications

### FR-1/FR-2: Progress Bar Display

**Input**: Start/completion events for each initialization step

**Processing**:
- Show progress bar on top screen during startup
- Visualize progress across 4 steps:
  1. System Init (romfs, ndsp, ndmu, soc, curl, etc.)
  2. Config Load (config.json, theme, wallpaper texture)
  3. Playlist Load (PlaylistManager::init)
  4. Server Connection (check_connection)
- Bar advances as each step completes
- Display current step name as text

**Output**: Progress bar + step name text on top screen

### FR-3: Spinner Redesign

**Input**: Frame updates during server connection check

**Processing**:
- Remove current `[/] [-] [\] [|]` text spinner
- Replace with animation within the progress bar at Step 4
  - e.g., pulsing bar tip, or animated stripe pattern inside the bar
- Keep "Connecting to server..." text

**Output**: Animated progress bar + text

### FR-4/FR-5: Timeout Handling

- 15-second timeout → error display → Retry / Change IP / Exit menu
- Existing flow is preserved; only visual style is unified with loading screen
- **Input method**: D-pad (up/down) to select menu item, A button to confirm
- No other input methods (no touch, no START/SELECT shortcuts)

## 3. UI/UX Considerations

### Loading Screen Layout (Top Screen)

```
+------------------------------------------+
|                                          |
|                                          |
|                                          |
|         [===========       ]             |
|         Step 3/4: Loading playlists      |
|                                          |
|                                          |
+------------------------------------------+
```

- Progress bar: centered, slightly above middle
- Step text: directly below the bar
- Background: default theme (config not yet loaded for early steps)

### During Server Connection (Step 4)

```
+------------------------------------------+
|                                          |
|                                          |
|                                          |
|         [==================>  ] (pulse)  |
|         Step 4/4: Connecting to server...|
|                                          |
|                                          |
+------------------------------------------+
```

- Step 4 waits for server response, so bar tip animates (pulse/stripe)
- On connection success, bar fills to 100% and transitions to home screen

### Timeout Error Menu

```
+------------------------------------------+
|                                          |
|         Connection Error (Timeout)       |
|                                          |
|       > Retry                            |
|         Change IP                        |
|         Exit                             |
|                                          |
+------------------------------------------+
```

- D-pad up/down to move cursor (`>`)
- A button to confirm selection
- Visual style unified with loading screen

## 4. Additional Design Info

### Implementation Constraints
- Progress bar can be drawn with `C2D_DrawRectSolid` (citro2d)
- Text rendering reuses existing `C2D_TextParse` / `C2D_DrawText`
- 3DS top screen resolution: 400x240

### Impact on Existing Code
- `main.cpp`: Modify loading screen rendering in startup sequence (lines 261-451)
- Timeout menu input handling: replace current button-based input (A/B/START) with D-pad + A only
- Whether to extract loading rendering into a helper function/file is decided in DESIGN phase
