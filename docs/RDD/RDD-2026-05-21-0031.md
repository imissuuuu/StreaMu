# RDD - 2026-05-21-0031
**Project Name:** Opus Performance Instrumentation

## 1. 機能一覧
- FR-1: Opus Direct 再生開始時の主要タイミングを計測できるようにする。
- FR-2: サーバー側 `/stream_opus_ogg` の初動と送信状況を既存 dashboard log で確認できるようにする。
- FR-3: 3DS側の受信・decode開始・実再生開始タイミングを端末側ログとして残す。
- FR-4: 計測追加によって Opus Direct / AAC Direct / MP3 Proxy / hidden Opus PoC の再生挙動を変えない。
- NFR-1: 計測処理は hot path で連続I/Oしない。閾値到達や状態遷移時だけ記録する。
- NFR-2: 計測ログ取得に失敗しても再生は継続し、fallback条件に影響させない。

## 2. 詳細仕様
### FR-1: Opus Direct タイミング計測
- 入力: Audio Path が Opus Direct の通常再生または seek 再生。
- 処理: 開始、first byte受信、16KB到達、download完了、decoder open開始/結果、audio started を記録する。
- 出力: 各段階の経過msがログから読み取れる。

### FR-2: サーバー側ログ
- 入力: `/stream_opus_ogg?i=<video_id>[&t=<seconds>]`。
- 処理: 既存の `add_log()` により、extract/cache後のstream開始、上流first byte、初回Ogg page、16KB送信、終了時の送信bytes/page数を記録する。
- 出力: `http://127.0.0.1:8080` の dashboard でサーバー側ボトルネックを確認できる。

### FR-3: 3DS側ログ
- 入力: Opus Direct 再生中の受信・decode状態遷移。
- 処理: `sdmc:/3ds/StreaMu/opus_perf.log` へ短い1行ログを追記する。
- 出力: 実機上で、ネットワーク受信とdecode開始/実再生開始の差分を確認できる。

### FR-4: 回帰防止
- 入力: 既存の再生操作。
- 処理: 計測は状態観測のみとし、buffer閾値、decode量、stream内容、fallback分岐は変更しない。
- 出力: 既存挙動を維持したまま、次の最適化判断に必要なデータを取れる。

## 3. UI/UX考慮事項
- 画面表示や操作体系は変更しない。
- 計測中であることをユーザー向けUIには表示しない。
- サーバーdashboardの既存ログ欄にサーバー側計測が出る。

## 4. 追加設計情報
- 主な影響範囲:
  - `source/network/youtube_api.cpp`: Opus stream受信タイミングを端末側ログへ記録する。
  - `source/main.cpp`: Opus decoder開始とaudio startedを端末側ログへ記録する。
  - `server/proxy.py`: `/stream_opus_ogg` generatorの送信タイミングを既存logへ記録する。
- 実機ログファイルを開けない場合は無視する。
- 本タスクでは page batching や decodeスケジューリング変更は行わない。計測結果を見て次タスクで判断する。
