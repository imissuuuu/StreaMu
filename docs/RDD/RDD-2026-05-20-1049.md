# 要件定義書 - Vorbis Playback PoC
**作成日:** 2026-05-20

## 1. 目的
AAC decoder 同梱の特許リスクを避ける代替候補として、追加済みの `VorbisStreamDecoder` を NDSP 再生経路に接続し、Ogg Vorbis を 3DS 側で実際に鳴らせるかを小さく確認する。

## 2. 機能要件
- FR-1: `VorbisStreamDecoder` の PCM16 出力を NDSP wave buffer に queue する Vorbis playback PoC 経路を追加する。
- FR-2: 完全受信済み、またはローカル相当の `.ogg` buffer を入力として再生開始できる。
- FR-3: Vorbis playback の開始、停止、buffer 再利用、track 終了判定を既存 player と同等の形で扱う。
- FR-4: 既存の AAC Direct と MP3 Proxy の通常再生、seek、Settings 表示は変更しない。
- FR-5: PoC の制限、実機確認項目、次の判断点を文書に残す。

## 3. 非機能要件
- NFR-1: `ctrmus` など GPL 実装からコードをコピーせず、devkitPro portlibs API を直接使う。
- NFR-2: NDSP buffer は `linearAlloc` / `linearFree` で管理し、raw `new` / `delete` は使わない。
- NFR-3: playback hot loop では不要な heap allocation と大きな object copy を避ける。
- NFR-4: 共有 stream buffer 参照は既存の `LightLock` 方針に合わせ、`std::atomic` は使わない。
- NFR-5: decode 失敗や入力不足で本体が固まらないよう、読み進められる byte 数または待機を明確に扱う。

## 4. 対象外
- YouTube 音源を Ogg Vorbis として供給するサーバー側変換の実装。
- Settings に正式な `Vorbis` Audio Path を追加すること。
- AAC Direct の削除、release build gating、または experimental compile-time option 化。
- Vorbis の長時間連続再生、seek、metadata 表示、音質チューニング。
- MP3 Proxy 経路や server-side FFmpeg transcode の削除。

## 6. 受け入れ条件
- `make clean` と `make` が通る。
- `VorbisStreamDecoder` を使う Vorbis playback PoC 経路が追加される。
- `.ogg` buffer を入力して NDSP wave buffer に PCM を queue できる実装になっている。
- AAC Direct と MP3 Proxy の既存コードパスに不要な挙動変更が入っていない。
- `git diff --check` が通る。
- 実機テスト手順として Vorbis 再生、AAC Direct 回帰、MP3 Proxy 回帰、終了判定確認が文書化される。
