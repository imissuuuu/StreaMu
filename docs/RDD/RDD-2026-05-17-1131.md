# RDD - 2026-05-17-1131
**Project Name:** StreaMu AAC PoC Seek Support

## 1. 機能一覧
- FR-1: `Audio Path = AAC PoC` の再生中に seek 操作を行っても、次曲送りとして扱わず、指定位置付近から再生を再開する。
- FR-2: AAC PoC の seek はサーバー側時間指定 ADTS 配信で実現し、3DS 側は ADTS ストリームのみを扱う。
- FR-3: AAC PoC の seek 後も通常再生、停止、次曲/前曲操作、再 seek が継続して動作する。
- FR-4: MP3 Proxy の既存 seek 動作と通常再生を回帰させない。
- FR-5: seek 位置が不正、負数、曲長超過、またはサーバー側で解決不能な場合でも、アプリはクラッシュせず失敗状態を扱える。
- NFR-1: 3DS 側に MP4/fMP4 パーサーを追加しない。AAC PoC のコンテナ解析はサーバー側に限定する。
- NFR-2: seek 処理は実機で使える応答性を目指し、長い曲でも先頭から大量に読み捨てる方式を採らない。
- NFR-3: 既存の FFmpegless Audio PoC の成果物と互換性を保ち、MP3 Proxy をデフォルト安定経路として維持する。
- NFR-4: 3DS C++ 実装では既存のメモリ管理、LightLock 同期、RAII 方針に従う。

## 2. 詳細仕様

### FR-1: AAC PoC seek 操作
- 入力: AAC PoC 再生中にユーザーが既存の seek 操作を行う。
- 処理: 現在再生位置から目標秒を計算し、その目標秒を使って AAC PoC ストリームを再開始する。
- 出力: 次曲へ遷移せず、目標秒に近い AAC フレーム境界から再生が再開される。

### FR-2: サーバー側時間指定 ADTS 配信
- 入力: 3DS クライアントから YouTube video id と開始秒を含む AAC ADTS ストリーム要求を受け取る。
- 処理: サーバーは YouTube の `m4a_dash` / fMP4 音声情報から開始秒に対応する AAC サンプル位置を解決し、その位置以降を ADTS として配信する。
- 出力: クライアントは従来と同じ ADTS ストリームとして受信し、AAC デコーダへ渡せる。

### FR-3: seek 後の継続操作
- 入力: seek 後に通常再生、停止、次曲/前曲、または再 seek を行う。
- 処理: AAC PoC の再生状態と現在位置を更新し、操作に応じた既存の再生制御を継続する。
- 出力: seek 後の再生が不安定化せず、操作不能や無限リトライにならない。

### FR-4: MP3 Proxy 回帰防止
- 入力: `Audio Path = MP3 Proxy` で既存の再生と seek を行う。
- 処理: 既存の MP3 Proxy 経路を変更する場合は、AAC PoC のための変更が MP3 の URL 生成、seek、再生制御を壊していないことを確認する。
- 出力: MP3 Proxy の既存操作は従来通り成功する。

### FR-5: 不正 seek 位置・失敗時の扱い
- 入力: 負数、曲長超過、極端に大きい値、またはサーバー側で開始位置を特定できない値を受け取る。
- 処理: 値を妥当範囲へ丸める、または明確な失敗として扱う。
- 出力: 3DS アプリはクラッシュせず、次曲送りとの誤認を避ける。曲長超過は終端付近または再生終了として扱える。

## 3. UI/UX考慮事項
- 既存の seek 操作 UI を維持し、AAC PoC 専用の新しい操作を増やさない。
- AAC PoC で seek 可能になったことを理由に、MP3 Proxy と異なる操作体系を作らない。
- seek 中の一時的な無音や再接続時間は許容するが、次曲に飛んだように見える挙動は解消する。
- エラー時は既存の再生失敗表示・状態遷移に合わせ、ユーザーに不可解な操作不能状態を残さない。
