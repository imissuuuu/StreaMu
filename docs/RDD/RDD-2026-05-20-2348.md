# RDD - 2026-05-20-2348
**Project Name:** Opus Playback Parity

## 1. 機能一覧
- FR-1: Opus Direct で既存再生経路と同等の seek 操作を可能にする。
- FR-2: Opus Direct の再生開始時間を実用レベルにする。
- FR-3: Opus Direct が実用レベルに達するまでは release 対象にしない。
- FR-4: Opus Direct が実用レベルに達した後、公式releaseでは ffmpeg 依存を外せる状態にする。
- FR-5: 既存の AAC Direct / MP3 Proxy / hidden Opus PoC の回帰を防ぐ。
- NFR-1: 3DS側のメモリ使用量とスレッド同期は既存の LightLock / streaming buffer 方針に従う。
- NFR-2: Opus失敗時の MP3 Proxy fallback は開発中の退避として維持するが、release品質の主条件にはしない。

## 2. 詳細仕様
### FR-1: Opus Direct seek
- 入力: ユーザーが PlayingScreen / SearchScreen / HomeScreen の seek bar で開始秒を指定する。
- 処理: Audio Path が Opus Direct の場合も seek 秒を破棄せず、Opus用stream URLへ渡す。
- 出力: 指定秒付近から Opus Direct 再生が開始され、再生バーは指定秒を基準に進む。
- 許容: Opus codec pre-roll や WebM/Ogg page 境界の都合で、実際の開始位置は目標秒の少し前でよい。

### FR-2: 再生開始時間
- 入力: Opus Direct で通常再生または seek 再生を開始する。
- 処理: サーバーは全量download/remuxを待たず、最初にdecode可能な Ogg Opus page を逐次返す。
- 出力: 既存経路と同等に近い待ち時間で音が出る。
- 目標: 現状の実機観測値である約4秒を悪化させない。可能なら短縮する。

### FR-3: release gating
- 入力: release判断時の再生品質確認。
- 処理: Opus Direct が seek と開始時間で実用レベルに達しているか確認する。
- 出力: 実用レベル未満の場合、Opus Direct をrelease本命にしない。

### FR-4: ffmpegless release path
- 入力: Opus Direct が実用レベルに達した後の公式release準備。
- 処理: Opus Direct は server-side ffmpeg transcode/remux に依存しない経路を維持する。
- 出力: 将来的に ffmpeg を公式配布構成から外せる。

### FR-5: 回帰防止
- 入力: Opus Direct parity 実装後の既存操作。
- 処理: AAC Direct / MP3 Proxy / hidden Opus PoC の既存挙動を保つ。
- 出力: 既存経路の通常再生、seek、fallback/debug用途が壊れない。

## 3. UI/UX考慮事項
- Opus Direct の seek 操作は既存の seek bar 操作と同じにする。
- 「Opus seek unsupported」のような特別扱い表示は、seek実装後は出さない。
- seek中は既存経路と同様に Buffering 表示を使う。
- fallback は開発中の退避であり、ユーザーにとって主要UXにしない。

## 4. 追加設計情報
- 主な影響範囲:
  - `source/main.cpp`: Opus seek 秒の破棄をやめ、再生状態とバー基準を維持する。
  - `include/network/youtube_api.h` / `source/network/youtube_api.cpp`: Opus stream URL に開始秒を渡す。
  - `server/proxy.py`: `/stream_opus_ogg` の `t` パラメータ対応。
  - `server/webm_opus_remux.py`: seek開始位置からdecode可能な Ogg Opus streamを生成する。
- 3DS側は WebM/Ogg の重い解析を担当しない。サーバーが seek可能な Ogg Opus stream を生成する。
- MP3 Proxy fallback は当面維持するが、release判断では「fallbackすればよい」とは扱わない。
