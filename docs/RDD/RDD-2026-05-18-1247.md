# RDD - 2026-05-18-1247
**Project Name:** AAC Direct Promotion

## 1. 機能一覧
- FR-1: 既定の音声経路を FFmpegless/AAC 直接再生へ変更する。
- FR-2: UI と設定表示から `PoC` 扱いを外し、正式経路として `AAC Direct` と表示する。
- FR-3: 既存の `aac_poc` 設定値は読み込めるようにし、既存ユーザー設定を壊さない。
- FR-4: MP3 Proxy は削除せず、移行期間の fallback/debug 用経路として設定から選択できる状態を維持する。
- FR-5: AAC 初期化に失敗する本体では MP3 Proxy へ退避し、起動不能にしない。
- NFR-1: 今回は経路の昇格と呼称変更に限定し、MP3 Proxy の実削除は移行完了後の別タスクにする。
- NFR-2: 3DS 側のスレッド同期、メモリ管理、描画ルールは既存の `coding-patterns.md` に従う。

## 2. 詳細仕様

### FR-1: 既定音声経路の変更
- 入力: 設定ファイルに `audio_path` が存在しない、または未対応値が入っている。
- 処理: アプリは AAC Direct を既定値として扱う。
- 出力: 新規ユーザーまたは未設定環境では AAC Direct 経路で再生する。

### FR-2: UI 表示の正式化
- 入力: Settings の `Audio Path` 行を表示する。
- 処理: AAC 経路は `AAC Direct` として表示し、説明文も主経路であることが分かる内容にする。
- 出力: ユーザーは AAC 経路を実験的 PoC ではなく標準経路として認識できる。

### FR-3: 既存設定互換
- 入力: 既存設定に `"audio_path": "aac_poc"` または `"audio_path": "mp3"` が保存されている。
- 処理: `"aac_poc"` は AAC Direct として読み込み、保存時は新しい値を使う。
- 出力: 既存ユーザーの設定は失われず、新形式へ自然に移行する。

### FR-4: MP3 Proxy fallback 維持
- 入力: Settings で `Audio Path` を切り替える。
- 処理: AAC Direct と MP3 Proxy の選択を維持する。
- 出力: AAC Direct に問題がある環境でも MP3 Proxy へ退避できる。

### FR-5: AAC 初期化失敗時の退避
- 入力: 起動時に AAC プレイヤー初期化が失敗する。
- 処理: AAC Direct が既定または選択中でも MP3 Proxy に戻す。
- 出力: アプリは起動し、MP3 Proxy で再生可能な状態を保つ。

## 3. UI/UX考慮事項
- Settings の `Audio Path` は引き続き同じ位置に置く。
- 表示値は `AAC Direct` / `MP3 Proxy` の 2 択とする。
- 説明文は短くし、AAC Direct が標準で MP3 Proxy は fallback/debug 用であることを示す。
